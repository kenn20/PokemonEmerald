## Summary

Prove the supplied Emerald ROM boots headlessly under PyBoyAdvance and reaches a visually verified title screen. This phase stops there: no route, RAM observation, inputs, starter branch, or JEV policy.

Prerequisite: add the BIOS at `bios/gba_bios.bin`. The current checkout has the ROM but no BIOS.

## Implementation changes

- Add a minimal Python environment definition pinned to `pyboy-advance==1.0.1`, plus NumPy and Pillow for framebuffer access/export.
- Implement `pyboy_adapter.py` with:
  - `PyBoyAdvance(rom=..., bios=..., skip_bios=False, emulation_speed=0)`
  - `frame(count)` and an adapter-owned frame counter.
  - `pixels()` returning the 240×160 RGB framebuffer.
  - No key or memory-write methods in Phase 1.
- Implement `prototype.py` as a headless CLI:
  ```bash
  python prototype.py \
    --rom "Pokemon - Emerald Version (USA, Europe)/Pokemon - Emerald Version (USA, Europe).gba" \
    --bios bios/gba_bios.bin \
    --frames 900 \
    --screenshot artifacts/phase1-title.png \
    --json
  ```
  It validates assets, computes and prints ROM/BIOS SHA-256 values, runs exactly 900 frames, saves the PNG, and emits JSON containing frame count, framebuffer dimensions, framebuffer SHA-256, and screenshot path.

- Visual proof: inspect `artifacts/phase1-title.png` and confirm it is Emerald’s title screen.
- Repeatability: rerun from reset; framebuffer SHA-256 must equal the reviewed baseline.
